# Обновление аимбота

## Что изменено

Рабочий код изменён только в `modules/aim.lua`. Новых зависимостей для запуска нет. Остальные исходные файлы и `models/angel_v2.pack` оставлены без изменений.

- Круг: диапазон **1–500**, исходно 240 вместо 120. Это радиус в пикселях при высоте экрана 1080; при другой высоте он масштабируется, как и раньше. Очень большой круг может выходить за края экрана. Область захвата при этом остаётся круговой и ограничена видимой частью экрана.
- Дальность: диапазон **1–800 м**, исходно 800 м вместо 400 м. Пересчёт 1 stud = 0,28 м сохранён из исходного проекта; конкретная игра может использовать собственный масштаб.
- Плавность: **0–10**, исходно **0**. Ноль непосредственно направляет камеру на выбранную точку каждый кадр. 1–10 сохраняют сглаживание: чем больше число, тем медленнее поворот и больше отставание от движущейся цели.
- Действующая цель удерживается, пока она жива, проходит фильтры, находится в круге, в пределах дальности и видна при включённой проверке видимости. Соседняя цель больше не перехватывает наведение просто из-за меньшей дистанции до центра экрана.
- Голова и тело берутся из текущих частей персонажа. Позиция головы не вычисляется по высоте корневой части. Ссылки на части перепроверяются каждый кадр при замене, удалении, переподчинении и подгрузке.
- Шея: используется текущая `NeckRigAttachment`, затем соединение `Neck` у R6/R15, затем локальная точка в нижней части головы. Поворот головы учитывается. Если головы нет, наведение на шею пропускается.
- Ноги: выбирается центр реальной ноги, а не пустой промежуток между двумя ногами. Выбранная нога сохраняется, пока существует; при её удалении выбирается другая доступная часть ноги.
- `Physics`, `Ragdoll` и `PlatformStand` сами по себе больше не означают смерть: некоторые игры используют их для положения лёжа. По-прежнему исключаются нулевое здоровье, состояние `Dead` и явные флаги смерти. Игра, оставляющая труп с положительным HP и без таких признаков, может потребовать отдельного адаптера.
- Видимость выбранной точки перепроверяется каждый кадр, а не по результату 80 мс назад. Потомки камеры исключены из луча. Поиск больше не прекращается после четырёх закрытых целей.
- Собственная свободная камера по-прежнему приостанавливает аимбот. Камера игры типа `Scriptable` сама по себе больше не выключает наведение.
- При закрытии удаляется принадлежащая модулю диагностическая функция `shitaro_aim`.

## Установка

1. Заменить **`ShitaroHub/modules/aim.lua`** в репозитории новым файлом и сохранить изменения в `main`.
2. Остальные рабочие файлы заменять не требуется. Полный архив содержит исходную структуру, ресурсы, новый модуль, эту заметку и автономные проверки.
3. Повторно запустить прежнюю команду, используя прямые кавычки и URL без Markdown-разметки:

```lua
getgenv().ShitaroConfig = {
    BaseUrl = "https://raw.githubusercontent.com/laaloaoahfg-coder/ShitaroHub/main/ShitaroHub/"
}
loadstring(game:HttpGet("https://raw.githubusercontent.com/laaloaoahfg-coder/ShitaroHub/main/ShitaroHub/loader.lua"))()
```

GitHub Raw может обновляться с задержкой. Загрузчик при новом запуске создаёт новый кэш Lua-модулей. Обновление в GitHub и запуск через Xeno здесь не выполнялись.

Для быстрого наведения оставить плавность **0**. Круг и дальность выбирать под карту; максимально большой круг не обязателен для точного слежения.

## Границы проверки

Это наведение камеры по текущим данным, полученным клиентом, а не изменение попаданий или серверных хитбоксов. Далёкие части, которые сервер перестал обновлять либо не передал из-за стриминга, скрипт не может восстановить достоверно. Автоматического определения баллистики, упреждения, падения пули, разброса и компенсации отдачи нет: игра, оружие и их параметры не предоставлены. Поэтому гарантировать попадания очередью на любой дальности нельзя.

Roblox, Xeno и целевая игра в среде проверки недоступны. Проверены синтаксис обычным парсером Lua 5.4 и поведение настоящего `modules/aim.lua` на имитации Roblox API. Проверка не заменяет компиляцию Luau и запуск в Roblox. В тестовой геометрии используются числа Lua double; интерполяция вращения упрощена и не заявлена как точная копия движка.

## Воспроизводимые проверки

Требуются CPython 3.9+ и системная динамическая библиотека Lua 5.4. Сторонние Python-пакеты не нужны. Из корня проекта:

```sh
python3 tools/check_aim.py
```

Если библиотека не обнаруживается автоматически:

```sh
python3 tools/check_aim.py --lua-library /path/to/liblua-5.4.so
```

Проверка разбирает все Lua-файлы и выполняет `tests/aim_regression.lua`, загружая настоящий модуль аимбота. Покрыты увеличенный круг, ограничения круга и дальности, наведение на дальнюю движущуюся цель со сбросом камеры каждый кадр, смена позы и частей персонажа, шея R6/R15, выбор реальной ноги, удержание и отпускание цели, фильтры, обновление видимости, свободная камера, смена камеры, сглаживание, масштаб экрана и завершение работы. Результаты конкретного запуска находятся в `tests/aim_test_results.txt`.

## Проверка в игре

- Проверить запуск без предупреждений `[shitaro/aim]` и наличие диапазонов 0–10, 1–500 и 1–800.
- С плавностью 0 проверить отдельно голову, шею, тело и ноги при приседании, прыжке и положении лёжа у видимой цели; повторить на дальней дистанции.
- Проверить, что стена прекращает наведение при включённой проверке видимости, смена позы не заставляет переключаться на соседнего персонажа, смерть и респавн корректно меняют цель.
- Проверить совместную работу с третьим лицом, сменой FOV, свободной камерой и повторным запуском меню.
- Для сообщения об ошибке указать игру, выбранную часть тела, плавность, дальность, ракурс и вывод `getgenv().shitaro_aim()`.

Откат: вернуть исходный `modules/aim.lua` из первоначального архива и перезапустить меню. Формат настроек загрузчика и кэш модели не менялись.
