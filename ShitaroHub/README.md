# ShitaroHub

Меню + ESP + камера + аимбот для Roblox, разбитое на папки и файлы. Запуск одной строкой через инжектор.

Во вкладке **прочее / misc** находятся настройки движения: скорость ходьбы, усиленный прыжок, плавное падение, экспериментальное отталкивание при касании и постоянное вращение. Каждый эффект включается отдельно и выключен по умолчанию. Сервер игры может ограничить или откатить изменения.

## Структура

```
ShitaroHub/
├── loader.lua        точка входа: качает и запускает остальное
├── core/
│   ├── ui.lua        окно, вкладки, настройки, палитра, курсор, выход
│   ├── models.lua    помощник для 3D-моделей
│   └── viewmodel.lua поиск «вьюмодели» (руки и оружие от первого лица)
├── modules/
│   ├── esp.lua       ESP: box, line, name, distance, skeleton, health
│   ├── camera.lua    FOV, третье лицо, свободная камера
│   ├── aim.lua       аимбот и круг FOV
│   ├── trigger.lua   триггер: стреляет, когда прицел уже на игроке
│   ├── movement.lua  скорость, прыжок и плавное падение
│   └── skins.lua     вкладка skins: смена модели игрока (карточка + сброс)
├── models/
│   ├── angel_v2.pack модель «Ангел» (меши + текстуры + превью одним файлом, 5,4 МБ)
│   ├── manifest.lua  список моделей для core/models.lua
│   └── README.md
└── tools/
    └── build_angel_pack.py  конвертер .glb в .pack (нужен только для пересборки)
```

## Запуск

Репозиторий: `laaloaoahfg-coder/ShitaroHub`, ветка `main`. Команда для инжектора:

```lua
loadstring(game:HttpGet("https://raw.githubusercontent.com/laaloaoahfg-coder/ShitaroHub/main/ShitaroHub/loader.lua"))()
```

`BASE_URL` в первых строках `loader.lua` указывает на папку, в которой лежит сам `loader.lua`, поэтому заканчивается на `/ShitaroHub/`. Если репозиторий другой, поменяй его: без папки в пути `core/ui.lua` не скачается.

## Загрузка на GitHub

Сохрани те же пути, что в структуре выше: `core/ui.lua`, `modules/esp.lua` и так далее. Через сайт: **Add file → Create new file**, в поле имени пиши путь с косой чертой (`core/ui.lua`), GitHub сам создаст папку. С компьютера можно перетащить папки целиком через **Upload files**.

## Локальный запуск (без интернета)

Положи папку в `workspace` инжектора под именем `ShitaroHub`:

```lua
getgenv().ShitaroConfig = { Mode = "local" }
loadstring(readfile("ShitaroHub/loader.lua"))()
```

## Вкладка skins

Открой вкладку **skins**: там карточка с аниме девушкой. Нажми на неё, и твой персонаж получит её модель. Кнопка **reset** возвращает обычный вид. Модель переживает респавн.

- Видно только тебе: это меняется на твоём клиенте, другие игроки видят обычного персонажа.
- При первом открытии вкладки файл `models/angel_v2.pack` скачивается один раз в папку `ShitaroHub/cache` инжектора и дальше берётся оттуда.
- Нужен инжектор с `writefile`, `readfile`, `isfile`, `makefolder` и `getcustomasset`. Если их нет, внизу карточки появится сообщение.
- Переключатель **flip faces** нужен, только если модель выглядит наизнанку (внутренности вместо поверхности). Включи его, и модель пересоберётся.
- Подходят R15 и R6. Размер модели подгоняется под рост твоего аватара.
- Скин прячет только само тело (части тела, аксессуары, лицо). Оружие, инструменты и любые модели, которые игра приваривает к руке, остаются видимыми и переносятся в ладонь модели.
- От первого лица руки вьюмодели (руки и оружие, которые игра рисует у камеры) заменяются руками модели: настоящие руки прячутся, оружие остаётся.
- Кнопка **copy diagnostics** копирует в буфер описание того, как устроена игра (что лежит под камерой, какие детали сварены с рукой). Если что-то выглядит не так, пришли этот текст.
- Если игра в новом раунде возвращает настоящую модель или заменяет части тела, скин сам прячет её обратно или пересобирается (проверка 4 раза в секунду).

Как это устроено: модель разрезана на 36 кусков по частям тела R15. Каждый кусок это `Part` с `SpecialMesh`, приваренный к своей части тела, поэтому он двигается вместе с анимациями. Из-за этого на сгибах (локти, колени) бывают небольшие щели.

## Камера

- **Третье лицо и свободная камера** прячут вьюмодель тремя способами: всё, что лежит под камерой; папки в Workspace с именами вроде `ViewModels` / `FirstPerson`; любая деталь рядом с камерой, которая «приклеена» к ней и двигается вместе с ней.
- **Свободная камера** только камера: персонаж стоит, убирается оружие (`Tool`), перехватываются вызовы игры с именами вроде `Shoot` / `Fire` / `Attack` и ответ «кнопка мыши нажата» (нужен `hookmetamethod`, без него этот шаг пропускается). Выключил камеру, и оружие возвращается в руки.

## Быстрая ходьба и прыжки

Открой **прочее / misc → движение**. Отдельные переключатели включают быструю ходьбу, усиленный прыжок и плавное падение; все они по умолчанию выключены. Ползунок **скорость** меняет скорость ходьбы (1–200), **сила прыжка** — высоту и дальность прыжка при беге (20–140), а **сила падения** — поведение спуска (10–100%: меньше — медленнее). Чтобы прыгнуть дальше, разгонись и нажми обычную кнопку прыжка. Плавное падение действует только во время свободного падения, а не при подъёме, плавании или сидении.

Параметры применяются только к локальному персонажу, переживают респавн и отключаются при закрытии хаба; общая гравитация мира не меняется. При свободной камере управление движением приостанавливается. Игра или сервер могут вернуть обычные значения, ограничить движение или засчитать урон от падения. В Roblox/Xeno новая функция ещё не проверена — сначала пробуй невысокие значения и небольшую высоту.

Переключатель **«отталкивание (тест)»** при касании пытается применить импульс к другому игроку, если доступная в executor функция `isnetworkowner` подтвердила управление его физикой. В остальных случаях на 0,6 секунды включается вращение собственного персонажа, пытаясь передать импульс столкновением. Есть ограничение частоты; посторонние объекты и свой персонаж исключены. **Может отбросить вас вместо противника**, а при отключённых столкновениях или ограничениях сервера противник может вообще не сдвинуться. Успешный вызов импульса не означает, что его принял сервер.

Оба режима используют прерывистое вращение: целевая скорость 600 рад/с на 0,2 секунды, затем 0 на 0,1 секунды; фактическая скорость может быть ниже. Это эксперимент по мотивам публичных fling-скриптов, а не их точная копия: масса персонажа и столкновения не меняются. Независимый переключатель **«крутиться всегда»** запускает этот цикл заранее и продолжает его до выключения, с попыткой удерживать вертикаль и временным отключением автоповорота персонажа. Оба переключателя выключены по умолчанию. При совместном включении силы вращения не складываются. Выключение переключателя, закрытие хаба, посадка и свободная камера останавливают соответствующее вращение; после вставания или выхода из свободной камеры постоянный режим возобновляется. При респавне старый эффект очищается. Если физические компоненты недоступны, вращение не запускается. **Вращение может опрокинуть или отбросить вас**, даже с удержанием вертикали. Проверки выполнены на макетах, не в Roblox/Xeno; результат в конкретной игре неизвестен.

## «Блок Страйк»

Первое исправление для нестандартных персонажей и скрытых PVS-моделей описано в [BLOCK_STRIKE_UPDATE.md](BLOCK_STRIKE_UPDATE.md). Диагностические скрипты и инструкции находятся в [diagnostics/](diagnostics/README.md).

## Как это устроено

`loader.lua` скачивает `core/ui.lua` и запускает его. Ядро строит общий контекст и по очереди загружает `esp`, `camera`, `aim`, `trigger`, `skins` и `movement`. Если один модуль не скачался или упал, остальные работают, а причина пишется в консоль через `warn`.

`core/ui.lua` остался одним файлом (около 3 100 строк): его части связаны десятками общих переменных.
